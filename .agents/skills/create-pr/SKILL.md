# Create PR

요청한 변경을 리뷰 가능한 GitHub PR로 만든다. 명시적인 PR 생성 요청은 해당 변경의 커밋, 필요한 브랜치 생성, 일반 push와 PR 게시를 포함한다. 이미 승인된 범위에 추가 확인을 요구하지 않는다. 스킬 자체를 만들거나 수정하는 요청만으로 실제 PR을 게시하지 않는다.

## 실행 주체

- 이 스킬을 읽고 적용하는 실행 주체는 전담 서브 에이전트다. 메인 에이전트는 스킬 설명을 기준으로 작업을 위임하며, 직접 아래 PR 작업 절차를 실행하지 않는다. 메인 에이전트에 본문이 로드된 경우에도 위임 안내만 적용하고 전담 서브 에이전트에 넘긴다.
- 메인 에이전트는 전담 서브 에이전트 하나에게 “전달한 SKILL.md를 직접 읽고 $create-pr 스킬을 사용해 PR을 생성하라”고 지시한다. 저장소 절대 경로, 이 SKILL.md의 절대 경로, 사용자 요청, 알려진 변경 범위, base/head/remote, 검증 결과와 승인 범위를 전달한다. 알려지지 않은 값은 추측하지 않고 서브 에이전트가 확인한다.
- 전담 서브 에이전트는 이 파일과 필요한 references를 직접 읽은 뒤 아래 대상 확인부터 검증, 커밋, push, PR 생성과 결과 확인까지 수행한다. 다시 PR 생성 에이전트를 만들지 않는다.
- 메인 에이전트는 해당 저장소를 동시에 수정하거나 커밋·push하지 않고 완료를 기다린다. 서브 에이전트는 PR URL, base/head, head SHA, 검증 결과와 차단 원인을 반환한다. 메인 에이전트는 결과를 확인하고 현재 채팅에 PR을 첨부해 사용자에게 전달한다.
- 서브 에이전트 도구가 없으면 직접 게시로 대체하지 말고 실행 제약을 알린다.

## 대상 확인 절차

- 적용되는 AGENTS.md, Git 상태, staged/unstaged/untracked 변경, 현재 브랜치와 upstream, remote, 최근 커밋, PR 템플릿을 확인한다. 원격 정보를 갱신하고 base 대비 최종 커밋과 diff를 읽는다. 작업 트리가 깨끗해도 미게시 커밋이 있으면 PR 대상이다.
- 사용자가 지정한 base/head/remote를 우선한다. 별도 지정이 없으면 원격 기본 브랜치를 base로 사용한다. 여러 remote나 작업 묶음 때문에 대상을 판단할 근거가 부족하면 구체적인 선택지를 묻는다.
- 사용자 작업을 보존하고 요청 범위에 해당하는 파일만 포함한다. 비밀정보나 관련 없는 변경을 일괄 staging하지 않는다.
- 기본 브랜치에서 작업 중이면 직접 push하지 않고 프로젝트 규칙에 맞는 작업 브랜치를 만든다. 별도 규칙이 없으면 `codex/` 접두사를 사용한다. 기존 커밋을 임의로 reset하거나 이력을 재작성하지 않는다.
- 최신 base 대비 변경이 없으면 빈 커밋이나 가짜 PR을 만들지 않고 그 사실을 알린다. 동일한 저장소·base·head의 열린 PR이 있으면 중복 생성하지 않고 기존 PR을 반환한다. 메타데이터는 요청 범위에 필요한 경우만 수정한다.

## 검증과 커밋

- 저장소 규칙과 변경 범위에 필요한 lint, 테스트, 빌드를 실행한다. 동일한 최종 상태에서 이미 실행한 유효한 검사 결과는 재사용할 수 있다. 실패하거나 실행하지 못한 검사를 성공으로 표시하지 않는다.
- 관련 실패는 저장소의 TDD 규칙에 따라 수정한다. 무관한 실패나 접근 문제로 범위가 커지면 근거를 알리고 필요한 판단을 묻는다. 필수 검사 실패 상태에서는 준비 완료 PR을 게시하지 않는다. 사용자 요청이 있으면 실패를 명시한 draft를 만든다.
- 미커밋 변경은 요청 범위만 커밋한다. 사용 가능한 프로젝트 커밋 스킬이 있으면 이를 따르고, 없으면 저장소 커밋 규칙을 따른다. 이미 커밋된 변경에는 불필요한 커밋을 추가하지 않는다.

## 게시

- GitHub 커넥터가 필요한 기능을 제공하면 우선 사용한다. 로컬 push나 지원하지 않는 기능은 Git 또는 인증된 `gh` CLI로 처리한다. 토큰을 채팅에 붙여넣으라고 요구하지 않는다.
- 올바른 remote에 일반 push하고 원격 head SHA가 로컬 커밋과 같은지 확인한다. push 거절 시 최신 원격 상태와 원인을 확인한다. 자동 force-push, 보호 규칙 우회, 반복적인 쓰기 재시도를 하지 않는다.
- 아래 언어 선택 기준에 따라 해당 references 템플릿만 읽는다. 제목은 최종 결과를 구체적으로 표현하고, 본문에는 해결한 문제와 동작 변화, 실제 검증 결과, 중요한 제한을 변경 규모에 맞게 적는다. 확인하지 않은 주장이나 수행하지 않은 테스트를 넣지 않는다.
- draft 요청을 존중한다. 그 외에는 필수 검사를 통과한 준비 완료 PR을 생성한다. base/head를 명시하고, 생성 응답이 불명확하면 재시도 전에 기존 PR을 조회한다. `gh`로 여러 줄 본문을 전달할 때는 임시 UTF-8 파일과 `--body-file`을 사용한다.
- 생성된 PR의 URL, base/head와 상태를 확인한다. Codex 앱에서 `attach_artifact` 도구를 사용할 수 있으면 PR을 현재 채팅에 첨부한다.
- 최종 응답에는 PR 링크와 검증 결과를 간결하게 제공한다. 게시가 막히면 완료된 로컬 작업과 정확한 차단 원인을 구분한다. merge, 리뷰 요청, 라벨·담당자 지정은 별도 요청이 있을 때 수행한다.

## 언어와 템플릿 선택

- 사용자의 명시적 PR 언어 지정이 우선이다. 다음으로 대상 저장소의 CONTRIBUTING, PR 템플릿 및 최근 PR의 작성 관례를 확인한다. 대화 언어나 소유자 이름만으로 프로젝트 언어를 판단하지 않는다.
- 해외 오픈소스 또는 영어로 기여를 받는 프로젝트에는 [영문 템플릿](references/pr-template.en.md)을 사용하고 제목과 본문을 영어로 작성한다.
- 한국어로 기여를 받는 한국 프로젝트에는 [한국어 템플릿](references/pr-template.ko.md)을 사용하고 제목과 본문을 한국어로 작성한다.
- 저장소 자체 PR 템플릿이 있으면 필수 항목과 구조를 우선 보존하고 선택한 언어 템플릿의 작성 지침을 적용한다. 저장소 템플릿을 임의로 번역해 필수 필드를 바꾸지 않는다.
- 언어 근거가 없거나 충돌하면 게시 전에 영문·한국어 중 선택을 묻는다. 확인 중에도 diff 검토와 검증은 진행할 수 있다.
